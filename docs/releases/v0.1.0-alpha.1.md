# ProxiGaz v0.1.0-alpha.1

**Release type:** Limited staging alpha for API evaluation; not a completed Sprint 1 release or a production pilot.  
**Source:** `main` commit selected when the release workflow is dispatched.  
**Container:** GHCR image is recorded by immutable digest in the published GitHub Release.

## Included

- Admin login and vendor onboarding/profile management.
- Separate vendor activation and deactivation endpoint.
- Paginated admin vendor listing with active-status and name filters.
- Vendor bearer-session validation, rotation, and revocation; only token hashes are stored.
- Request validation and PXG-015 hardening.

## API and database impact

The API includes vendor list/status and vendor session operations added by PXG-013–015. Liquibase initializes PostGIS and applies the current core/User/Vendor schema changelog. Migrations are forward-only; take and verify a database backup before applying them to a shared environment.

## Known limitations

- Vendor brands and availability (Epic 1.2), nearby search (PXG-020/021), and the customer order flow are not implemented.
- There is no frontend. Evaluation is through Swagger UI or an API client.
- This alpha does not complete Sprint 1 and is not approved for production.

## Staging acceptance

- [ ] GitHub release workflow unit, data, and E2E checks pass.
- [ ] The published image digest deploys successfully to staging.
- [ ] `/actuator/health` reports `UP` and unauthenticated vendor session access is rejected.
- [ ] Sprint acceptance scenarios are reviewed in staging and approved through the `release-approval` environment.

## Rollback

If container health or auth smoke checks fail, the deployment script restores the prior application image. It does not reverse database migrations. For a schema issue, use a new forward migration; do not assume that restoring an older image restores the database schema.
